## 1. Эмодзи вместо иконок — 39 глифов в 5 файлах

| Где | Было |
|---|---|
| `js/shop.js` (14) | 🚚 «До прибытия», ⚠ «Рейс задерживается», 📦 «Ожидается со дня на день», ✅ «В Молдове с», 🔒 бронь (×3), 💡 скидки (×2), 📞 звонок, 💬 WhatsApp, ✕ закрыть, ✔ «Подтвердить бронь», ✉ «E-mail» |
| `admin.html` (5) | 📦 Техника, 🚚 Контейнеры, 🔔 Заявки, 👥 Роли, ← назад |
| `README.md` (4), `docs/` (14), `tests/` (2) | 🚚📦⚠✅🔴🟠🟡❌ в таблицах и выводе тестов |

**Чем это плохо.** Вся остальная вёрстка сайта построена на инлайновых SVG (24×24, `stroke: currentColor`, толщина 2):
шапка, преимущества, преимущества в подвале, карточки, соцсети. Эмодзи — это

- чужая графика: цветной «мультяшный» глиф в блоке, где рядом стоят зелёно-серые контурные иконки;
- неуправляемый цвет: `currentColor` на эмодзи не действует, а в тёмном оверлее избранных карточек
  жёлтая коробка и красный треугольник спорят с фотографией;
- разный рендер: на Windows, macOS, Android и iOS это четыре разные картинки — макет нельзя показать клиенту
  как эталон;
- смысловой шум: 📦 обозначало «ожидается со дня на день», 🚚 — «до прибытия», то есть грузовик и посылка
  поменялись местами по смыслу.

**Стало.** Добавлен маленький хелпер `ico(name)` в `js/shop.js` (11 иконок: грузовик, часы, треугольник, галочка,
замок, крестик, телефон, чат, процент, конверт, куб, колокол, люди, стрелка) и класс `.ico` в CSS
(16 px, `flex-shrink: 0`, `color: currentColor`). Разметка админки и «Как купить» переведена на такие же SVG.
Из `README`, `docs/` и вывода тестов эмодзи убраны — приоритеты в ТЗ теперь `P1/P2/P3`, тесты печатают `OK/FAIL`.

## 2. Цвета вне дизайн-системы — 22 значения

Было (только в блоке доработок): `#B45309`, `#6B7280`, `#FFF7ED`, `#FED7AA`, `#9A3412`, `#A16207`, `#FDE3C4`,
`#EA580C`, `#F0FDF4`, `#BBF7D0`, `#166534`, `#15803D`, `#DCFCE7`, `#FEF2F2`, `#FECACA`, `#991B1B`, `#B91C1C`,
`#FFFBEB`, `#FDE68A`, `#92400E`, `#1F2937` + `linear-gradient(90deg, var(--accent), #EA580C)`.

Проблемы по существу:

1. **Стоковый стикер не проходил по контрасту.** `.st-stock` — белый текст на `--primary` (#16A34A) = **3.3:1**,
   а кегль всего 12.5 px: по WCAG AA нужно ≥ 4.5:1. Текст на цветной плашке читается плохо, особенно на солнце
   и на телефоне в поле — а это и есть аудитория сайта.
2. **Пульсирующая точка на «В дороге»** (`@keyframes stPulse`, 1.8 s бесконечно) — движение в 14 карточках
   одновременно; сайт выглядел «мигающим».
3. **Радуга из трёх тинтов у счётчика**: оранжевый (в пути), зелёный (≤ 7 дней), красный (задержка) + зелёный
   «в стране». Четыре разных фона на одном экране каталога, при том что в дизайн-системе нет ни одного тинта
   для информации — только `--primary-50`, `--bg` и `--border`.
4. **Цвета не переиспользовались**: `#BBF7D0` (рамка) и `#DCFCE7` (`--primary-light`) — фактически один и тот же
   оттенок в двух написаниях; `#166534`, `#15803D` и `--primary-dark` — тоже почти одно и то же.
5. **Янтарный и коричневый рядом**: `#B45309` (бронь) и `--accent` #F59E0B (дорога) визуально сливаются,
   хотя статусы разные.
6. **Тёмная карточка контейнера** (`background: var(--dark)`) — единственное тёмное пятно среди белых карточек
   сайта; тёмный фон на сайте есть только у секции статистики и подвала.

**Стало.** В `:root` добавлен семантический набор — пять статусов по три значения:

```css
--st-stock-fg: var(--primary-dark);  --st-stock-bg: var(--primary-50);  --st-stock-bd: var(--primary-light); /* 4.8:1 */
--st-transit-fg: #B45309;            --st-transit-bg: #FFFBEB;         --st-transit-bd: #FDE68A;            /* 4.8:1 */
--st-reserved-fg: var(--dark);       --st-reserved-bg: #F3F4F6;        --st-reserved-bd: var(--border);     /* 16:1  */
--st-sold-fg: #4B5563;               --st-sold-bg: #F3F4F6;            --st-sold-bd: var(--border);         /* 7.2:1 */
--st-late-fg: #B91C1C;               --st-late-bg: #FEF2F2;            --st-late-bd: #FECACA;               /* 5.9:1 */
```

- Значения, уже существовавшие в системе (`--primary-dark`, `--primary-50`, `--primary-light`, `--dark`, `--border`),
  теперь берутся ссылкой, а не копией; новых «просто цветов» четыре пары, и они переиспользуются везде:
  стикер, счётчик, плашки, контейнеры, скидки, админка.
- Контраст каждой пары «текст на фоне» посчитан и указан в комментарии — все ≥ 4.5:1.
- Пульсация удалена. Проданная позиция теперь ещё и приглушается (`.product-card[data-status="sold"] .product-card-image { opacity: .72 }`) —
  статус читается без разглядывания стикера.
- Тёмная карточка контейнера заменена на обычную белую карточку дизайн-системы.
- Градиент на полосе прогресса заменён на одноцветную заливку `--primary` по треку `--border`.

## 3. Счётчик поставки: было три разных блока — стал один

Было: четыре состояния с четырьмя разными заливками, эмодзи внутри строки, янтарный текст `#9A3412` на кремовом
фоне, зелёный блок для «днями» и «в стране», красный для задержки.

**Стало:** одна нейтральная плашка (белая, `--border`, `--radius`), состояние передаётся **иконкой и цветом строки**:

| Состояние | Иконка | Оформление |
|---|---|---|
| До прибытия N дней | грузовик | цвет иконки `--primary`, цифры выделены `<b>` |
| Ожидается со дня на день | часы | цвет иконки `--accent-dark` |
| Рейс задерживается | треугольник | единственное исключение: фон `--st-late-bg`, рамка `--st-late-bd`, текст `--st-late-fg` |
| В Молдове с … / в наличии | галочка в круге | нейтрально, `--primary` |

Так страница не «кричит» четырьмя цветными прямоугольниками, а важное (задержка) остаётся заметным.
В тёмном оверлее избранных карточек счётчик переопределён: без рамки и фона, белый текст, белая полоса прогресса.

## 4. Третий шрифт, которого в системе нет

Моноширинный (`ui-monospace, SFMono-Regular, Menlo, monospace`) подключался в пяти местах: код контейнера на фото,
серийный номер в характеристиках, подпись в модалке, `.cont-code`, `.book-sub`.

В дизайн-системе ровно один шрифт — Inter, с весами 300–800. Моноширинный у системного шрифта ещё и разный на
каждой ОС, из-за чего метка контейнера и серийник выглядели по-разному в разных браузерах.

**Стало:** Inter + `font-variant-numeric: tabular-nums`. Цифры дат, серий и счётчиков выравниваются по разрядам
(это и было целью моно), но типографика остаётся одной.

## 5. Композиция главной: две белые секции подряд

Коммит вставил «Контейнеры в пути» с `background: var(--white)` сразу после белой секции каталога, а «Как купить» —
с `--bg`. Ритм секций главной (`белая / серая / тёмная`) сломался: две белые подряд, затем серая, затем тёмная.
Поменяны местами: контейнеры — `--bg`, «Как купить» — `--white`; дальше как было: тёмная статистика → серая
преимущества.

  Заменено на принятый в проекте фокус формы: `border-color: var(--primary)`, `outline: none`.
- Кнопка «сбросить» и ссылка «сбросить» в одном блоке; у второй теперь аккуратный `.link-btn` с подчёркиванием
  и ховером, а не «синий текст по умолчанию».
- Ширина `.cont-strip` 250 px → 240 px, `gap` 16 → 20 px: карточки контейнеров встают в ту же сетку, что

## 7. Настоящие барые дефекты, найденные попутно

Это не оформление, но их стоит зафиксировать в том же коммите правок:

### 7.1. Сломана разметка `catalog.html` и `product.html`

Последний коммит вырезал статические карточки из каталога и похожих товаров, но оставил незакрытыми
`<div class="container">` и `<section>`: счётчик тегов показывал `div 27/26`, `section 3/2`.

```html
<!-- было: CTA-секция оказывается внутри секции каталога -->
<div class="products-grid" id="products-grid"></div>

<!-- CTA -->
<section class="cta"> … </section>
</main>
```

Браузер такое «починит», но CTA с формой попадала внутрь `.section` каталога, наследуя отступы и фон, а
`.products-grid` и `.catalog-toolbar` — в чужом контексте. Закрывающие теги восстановлены, парность тегов
сходит: `div 27/27`, `section 3/3`.
Заодно удалён мёртвый инлайн-скрипт в `catalog.html`: он «нажимал» кнопку фильтра до того, как `shop.js`
навешивал обработчики (то есть не делал ничего — фильтр по `?cat=` и так читается в `init()`).

### 7.2. Кнопка внутри ссылки в карточке товара

```html
<a href="product.html?id=1" class="product-card"> … <button data-act="book">Забронировать</button>  </a>
```

Вложенная интерактивность — невалидный HTML и минное поле для клавиатуры и скринридеров (в базовой вёрстке
внутри `<a>` уже жила кнопка «В избранное», коммит добавил вторую). Карточка перестроена на схему
«растянутая ссылка»:

```html
<article class="product-card" data-id="1" data-status="transit">
  <a class="product-card-hit" href="product.html?id=1" aria-label="Трактор John Deere 8R"></a>
  <div class="product-card-image"> … стикер, метка контейнера, избранное, оверлей … </div>
  <h3>…</h3><div class="product-card-price">…</div>…<button class="product-card-book">…</button>
</article>
```

`.product-card-hit` растянут на всю карточку (`inset: 0`, `z-index: 1`), кнопки сидят выше (`z-index: 2`),
декоративный оверлей «Подробнее» получил `pointer-events: none`, у стикеров и метки — тоже, чтобы не гасили клик.
Фокус с клавиатуры теперь видно (`.product-card-hit:focus-visible`).

### 7.3. Хранимая XSS в админке

Данные из публичной формы брони (`name`, `phone`, `comment`) писались в `localStorage` и вставлялись в
`admin.html` через `innerHTML` без экранирования:

```js
box.innerHTML = list.map((b) => `<div class="admin-who">${b.name} · <a href="tel:${b.phone}">…`)
```

Достаточно было в поле «Имя» ввести `"><img src=x onerror=…>`, чтобы у менеджера, открывшего админку, выполнился
чужой код — а менеджер смотрит админку с тем же `localStorage`. Добавлен `esc()` и применён ко всем данным,
попадающим в `innerHTML` (имена, серия, контейнер, описания).

### 7.4. Предзаполненная галочка согласия

`<input type="checkbox" required checked>` — согласие на обработку персональных данных было отмечено заранее.
Это и юридически спорно, и противоречит требованию «действие пользователя должно быть осознанным».
Атрибут `checked` убран, у полей появились `autocomplete` и связанные `<label for>`; модалка закрывается
по `Esc`, фокус уходит в первое поле, скролл страницы под модалкой блокируется.

### 7.5. Мелочи из той же серии

- В фильтре статуса не было опции **«Продан»** — статус нельзя было выбрать, хотя в данных он есть. Добавлен.
- В админке название позиции и даты всегда печатались по-русски, даже при переключении на RO: теперь по языку
  интерфейса. Половина текстов `admin.html` вообще не имела `data-i18n` — добавлено 19 новых ключей RU/RO (38 строк)
  (очередь заявок, план админки WordPress, примечание, подвал).
- `enhanceFeatured()` выставлял `host.style.position = 'relative'` из JS — `.featured-card` и так `position: relative`;
  строка убрана.
- Инпут `#shop-search` получал `data-i18n`, а остальные подписи фильтра имели `aria-label` только у части
  элементов; добавлены `aria-label` для селектов и полей админки, `aria-labelledby` для диалога.

## 9. Как проверялось

```
1) node tests/ui-test.mjs        -> 64 пройдено, 0 провалено   (базовые 53 из них проходили и до правок — регрессий нет)
2) node tests/design-check.mjs   -> проверка дизайн-системы пройдена
3) Живое превью на локальном сервере: index.html, catalog.html, product.html?id=1, admin.html
```

`tests/design-check.mjs` — новый скрипт, он падает, если:

1. в интерфейсных файлах появились эмодзи;
2. в блоке доработок CSS использован цвет вне `var(--…)` (исключений нет: даже красный для тёмного оверлея —
   токен `--st-late-fg-dark`);
3. `var(--x)` ссылается на несуществующую переменную;
4. `data-i18n`-ключ или `t('ключ')` отсутствует в словаре RU/RO (и у ключа нет перевода RO);
5. нарушена парность контейнерных тегов в HTML-страницах;
6. на любой странице появился инлайновый `style=""` или вернулся старый инлайновый приём.

Это защита от повторения истории: следующая правка «на глазок» упадёт на проверке, а не в продакшене.

## 10. Второй проход: «максимально по палитре, шрифтам и системе»

После первичных правок оставался один класс расхождений — **инлайновые `style=""` по страницам** (33 штуки
в шести базовых файлах). Это тоже часть дизайн-системы: инлайновый стиль невозможно переиспользовать,
он расходится с CSS и перебивает медиазапросы. Второй проход их убрал полностью:

| Что было инлайном | Класс системы |
|---|---|
| `style="background:var(--bg︎/--white)"` на 10 секциях | `.section--soft` / `.section--white` (работает и с `.about-section`) |
| `style="display:flex;align-items:center;gap:40px;"` в шапке всех страниц | `.header-left` |
| `style="color:var(--primary);"` у активного пункта меню | `.header-nav a.is-current` (отдельный цвет для прозрачной шапки на главной) |
